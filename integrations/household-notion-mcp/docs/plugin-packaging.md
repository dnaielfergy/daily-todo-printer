# Household plugin packaging and live acceptance

**Supported path:** OpenAI [Package your plugin](https://developers.openai.com/plugins/build/plugins) documents a root portable `plugin.json`, `skills/`, and `extensions.com.openai.apps: "./.app.json"` for **existing registered MCP connections**. We select this over `mcp.json` because our Cloudflare Access-protected MCP is already registered and OAuth-tested. `mcp.json` would need a private endpoint URL and reconfiguration of auth; neither belongs in this public repository. The repo contains **no** `.app.json`: its existing `plugin_asdk_app...` mapping is deployment-specific and must be assembled privately through official `@plugin-creator` / ChatGPT Plugins UI. Do not invent mapping JSON.

The plugin root is `integrations/household-notion-mcp/`; it already contains `skills/household-meal-planning/`. The plugin manifest includes both parts through standard fixed `skills/` discovery and the registered connection via `.app.json`. No second Skill installation is needed **once this combined plugin has been installed successfully**.

## One-time manual setup (required; not completed by GitHub CI)
1. In ChatGPT Plugins, locate the **existing authenticated Household MCP connection** and its `plugin_asdk_app...` technical ID. Do not register a new MCP or change Cloudflare OAuth if the existing one is working.
2. In ChatGPT Work mode invoke `@plugin-creator` or in Codex invoke `$plugin-creator`: request a plugin based on that **already registered** MCP ID, with the portable plugin root and its existing skill, and a private personal marketplace for testing. The creator generates a supported `.app.json` mapping; inspect and confirm it targets the original connection, not a new server. Keep mapping out of public Git and any public CI artifact.
3. Import/install the completed plugin from that marketplace or use the ChatGPT plugin submission/installation flow. In a **fresh conversation**, list installed skills, read `household-meal-planning`, then request a fictional recipe and fictional two-recipe dinner. Confirm the exact same MCP tools and Cloudflare Access authentication are available. For web, test this after installation: local marketplace features documented for ChatGPT Desktop/Codex are **not proof of web support**. If the workspace cannot install a custom combined package on web, record that limitation and do not claim web acceptance.
4. For Skill changes, merge reviewed code and refresh/reinstall/rescan the plugin package so that imported skill files update. Worker deploy is **not** a prerequisite for Skill-only changes. For MCP server/tool/instructions changes, merge then deploy the existing protected Worker, refresh the MCP connection, and verify initialization/tool listing.
5. Grocery/publish policy is read from the user's **configured authorized private inbox repository**, branch `main`, `policies/household.md` using connected GitHub every run. Repository selection is established privately with the user/connector, never by hardcoding names in the public Skill. If repository identity or read permission is not clear, stop policy-dependent work. Updating the private policy takes effect on next GitHub read; no Skill rescan or Worker deploy.

## Negative and protocol tests to finish
- Test ChatGPT web/desktop separately for installed Skill and all bundled references. Test direct and indirect prompts and no-trigger single MCP read.
- Read authorized private policy from `main` **after private PR is merged** (currently on a review branch); check exact ref/path, private visibility, and re-read on next run. Test missing connector, unauthorized private repo, missing/malformed policy and edits to an isolated private test fixture. Confirm independent recipe reads remain available.
- Test fixture dinner with two linked recipes and different base yields, meal serving override, documented leftover reuse, and ambiguous quantities. Keep basic seasonings/oil in recipe ingredients and steps but omit only currently policy-excluded shopping ingredients; retain similarly named vegetables/blends/alternative oils.
- In an authorized Cloudflare MCP session, inspect raw JSON-RPC `initialize` for `serverInfo` and advisory `instructions`; inspect `tools/list` descriptions. Test denied identity and disabled writes. Source inspection or SDK constructor support alone does **not** certify that Cloudflare transport/ChatGPT observes instructions.
- Create **no live meal**, private review publication, merge, active inbox change, Windows import or physical print during these checks. Keep both PRs unmerged until approval.

The Skill files and manifest may be validated without production credentials via `npm test` and `npm run check`. A **complete connected plugin package and fresh ChatGPT discovery cannot be CI-tested** without the workspace's registered MCP mapping/install flow.
